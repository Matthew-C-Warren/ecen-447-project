# Plan: `filters.m` — Wiener-Family Denoising Filters

## 1. Objective

`filters.m` implements seven Wiener-type denoising filters, applied to the
greyscale images already generated by `image_prep.m`
(`images/noisy/<noise_type>/<snr_x>/*.png`, with ground truth in
`images/clean/` and the mapping recorded in `images/noisy/noise_manifest.csv`):

1. **Classical Wiener** — spatial, local-statistics adaptive filter.
2. **Fourier Wiener** — global frequency-domain MMSE filter.
3. **Haar Wiener** — wavelet-domain empirical Wiener shrinkage, Haar basis.
4. **Daubechies Wiener** — wavelet-domain empirical Wiener shrinkage, dbN basis
   (db2, db4, db8 all compared — see §5.4).
5. **Meyer Wiener** — wavelet-domain empirical Wiener shrinkage, discrete Meyer basis.
6. **Shearlet Wiener** — shearlet-domain empirical Wiener shrinkage.
7. **Curvelet Wiener** — curvelet-domain empirical Wiener shrinkage.

All seven are pure **denoising** filters — none assume a blur/degradation
PSF. "Fourier Wiener" is the classic MMSE formula with the degradation
function `H = 1`, not a deconvolution filter; same denoising-only framing
applies to every other variant.

The file's job is purely algorithmic: take a noisy grayscale image in, return
a denoised image out. A separate driver/benchmark script (not part of this
plan's deliverable, but noted in §9) will loop over the manifest, call
`filters.m`, and record PSNR, SSIM, and execution time.

## 2. Inputs & Assumptions

- Images arrive as `double` matrices in `[0,1]`, single-channel (matches
  `image_prep.m`'s `normalizeImage`). `filters.m` does **not** read files or
  do colorspace conversion — that's the caller's job (`imread` + `im2double`
  + `rgb2gray` if needed).
- Image sizes vary (`cameraman`, `crowd`, `pattern` are different
  resolutions) — no code should assume square images or power-of-two
  dimensions. Wavelet/shearlet/curvelet transforms must handle arbitrary
  sizes (pad internally if a transform requires it, then crop back).
- Noise type/level is known at benchmark time (from the manifest) but
  `filters.m` should not hard-code noise statistics — see oracle vs. blind
  variance estimation below.

## 3. MATLAB Toolboxes / Packages

| Filter | Toolbox needed | Built-in or external? |
|---|---|---|
| Classical | Image Processing Toolbox (`wiener2`) | Built-in |
| Fourier | Image Processing Toolbox (`deconvwnr`) or plain `fft2`/`ifft2` | Built-in |
| Haar / Daubechies / Meyer | Wavelet Toolbox (`wavedec2`, `waverec2`, `wfilters`) | Built-in |
| Shearlet | **NSST Toolbox** (Easley/Labate/Lim, MATLAB File Exchange) or ShearLab 3D | **External** |
| Curvelet | **CurveLab** (curvelet.org, `fdct_wrapping`) or a File Exchange curvelet implementation | **External** |
| PSNR/SSIM/timing (benchmark script) | Image Processing Toolbox (`psnr`, `ssim`), `tic`/`toc` | Built-in |

Notes:
- `wiener2` already *is* the classical local-statistics Wiener filter — no
  need to reimplement it from scratch, though a custom local-mean/variance
  version is a reasonable alternative if we want to control the neighborhood
  gain formula directly.
- `deconvwnr(I, PSF, NSR)` with `PSF = 1` reduces to the pure frequency-domain
  MMSE denoising filter — this gives us "Fourier Wiener" almost for free. A
  hand-rolled version (`fft2`, build `H = Sxx./(Sxx+Snn)`, `ifft2`) is also
  straightforward and gives more control over the PSD estimate; plan allows
  either, falling back to a custom implementation if `deconvwnr`'s denoise-only
  mode behaves oddly.
- Wavelet Toolbox covers Haar (`'haar'`), Daubechies (`'db1'`…`'db45'`), and a
  **discrete approximation of the Meyer wavelet** (`'dmey'`) — the true Meyer
  wavelet has no compact support in either domain, so `'dmey'` is the standard
  stand-in used by every MATLAB-based implementation. Worth a one-line caveat
  in code comments so it isn't mistaken for a bug.
- **Shearlet and curvelet have no MathWorks toolbox** — these are the risky
  dependencies:
  - *Shearlet*: recommend the **NSST Toolbox** — pure `.m` files, no MEX
    compilation, easy to drop into the repo or path. ShearLab 3D is more
    "standard" in the literature but ships MEX binaries that need
    platform-specific compilation.
  - *Curvelet*: **CurveLab** is the reference implementation but requires
    accepting an academic license, downloading, and compiling MEX files
    (`fdct_wrapping`) — can be finicky on Windows. A pure-MATLAB File Exchange
    curvelet implementation (e.g. a UDCT-style transform) is a lower-risk
    fallback if CurveLab won't build on a teammate's machine in time.
  - **Fallback plan**: if neither toolbox can be installed on all team
    machines before the deadline, substitute a simple steerable-pyramid or
    Gabor-filter-bank "directional multiscale" transform in place of the true
    shearlet/curvelet transform, clearly labeled as an approximation in the
    report. This keeps the 7-filter comparison structure intact even if the
    exotic transforms fall through.
- Add a path/dependency check at the top of `filters.m` (or a small
  `checkDependencies.m` helper) that gives a clear error (`"NSST Toolbox not
  found on path — see Wiener_Plan.md §3"`) rather than a cryptic "undefined
  function" error, since teammates will be running this on different machines
  (the manifest CSV already shows absolute paths from a teammate's machine).

## 4. Public API

Single dispatcher, local helper functions per filter (same pattern as
`image_prep.m`: one exported function + private local functions below it).

```matlab
function [denoised, info] = filters(noisyImage, method, options)
%FILTERS Apply a Wiener-family denoising filter to a greyscale image.
arguments
    noisyImage (:,:) double
    method (1,1) string {mustBeMember(method, ...
        ["classical","fourier","haar","daubechies","meyer","shearlet","curvelet"])}
    options.NoiseVariance = "auto"        % numeric, or "auto" for blind estimate
    options.CleanReference (:,:) double = []   % optional, enables oracle variance
    options.WaveletLevel (1,1) double = 4      % haar/daubechies/meyer
    options.DaubechiesOrder (1,1) double {mustBeMember(options.DaubechiesOrder, [2 4 8])} = 4
    options.Neighborhood (1,2) double = [5 5]  % classical wiener2 window
end
```

`method = "daubechies"` is a family, not one fixed wavelet — the benchmark
script is expected to call it three times per image (`DaubechiesOrder` =
2, 4, and 8, i.e. `'db2'`, `'db4'`, `'db8'`) so the results table can compare
filter order within the Daubechies family, the same way it compares across
Haar/Meyer/etc. `filters.m` itself just needs to accept whichever order is
requested and map it to the right `wfilters` name (`"db" + order`).

- `info` (optional second output) carries diagnostics useful for the
  benchmark script without forcing `filters.m` to know about PSNR/SSIM:
  `info.noiseVarianceUsed`, `info.elapsedSeconds` (via internal `tic`/`toc`
  around the dispatch — cheap and keeps the benchmark script simpler),
  and method-specific extras (e.g. decomposition level actually used).
- `options.NoiseVariance = "auto"` → blind estimate from the image itself
  (robust MAD estimator, §6). Passing a numeric value overrides it. Passing
  `CleanReference` lets the benchmark script request an **oracle** variance
  (computed directly from `noisyImage - CleanReference`) to measure each
  filter's best-case ceiling performance separately from its blind/practical
  performance — useful since the manifest already has achieved SNR per image.

## 5. Per-Filter Design

### 5.1 Classical Wiener (spatial)
- Thin wrapper around `wiener2(noisyImage, options.Neighborhood, noiseVar)`.
- `noiseVar` comes from the shared estimator (§6) unless overridden.
- This is the cheapest filter — good as the baseline/sanity-check case.

### 5.2 Fourier Wiener (frequency domain)
- Estimate noise PSD as flat: `Snn = noiseVar` (white-noise assumption,
  reasonable for white/gaussian/uniform/exponential/rayleigh additive noise
  as generated by `image_prep.m`).
- Estimate signal PSD from the noisy image's periodogram minus `Snn`,
  clipped at zero: `Sxx = max(|FFT(noisyImage)|^2 - Snn, 0)`.
- Build filter `H = Sxx ./ (Sxx + Snn)`, apply as
  `ifft2(fft2(noisyImage) .* H)`, take `real(...)`.
- Equivalent to `deconvwnr(noisyImage, 1, noiseVar/signalVar)` if we'd rather
  lean on the toolbox function — keep both implementations in mind, pick
  whichever is cleaner once prototyped; behavior should match.

### 5.3 / 5.4 / 5.5 Haar / Daubechies / Meyer Wiener (wavelet domain)
All three share one local function, parameterized only by the wavelet name
(`'haar'`, `'db<DaubechiesOrder>'`, `'dmey'`):

1. `[C, S] = wavedec2(noisyImage, options.WaveletLevel, waveletName)`.
2. Estimate noise std via Donoho's MAD estimator on the finest-level
   diagonal detail coefficients: `sigma = median(abs(cD1)) / 0.6745`.
3. For each detail subband (horizontal/vertical/diagonal, each level), apply
   **empirical Wiener shrinkage** (shared helper, §6):
   `coeff_out = coeff_in .* (varSignal ./ (varSignal + sigma^2))`, where
   `varSignal` is a local-window variance estimate of that subband (not a
   hard/soft threshold — this is what makes it "Wiener" rather than
   generic wavelet denoising).
4. `waverec2(C_shrunk, S, waveletName)` to reconstruct.
5. Leave approximation (low-pass) coefficients untouched.

**Daubechies order sweep**: `options.DaubechiesOrder` is restricted to
`{2, 4, 8}` (`'db2'`, `'db4'`, `'db8'`) rather than one fixed value — longer
filters (db8) trade better frequency localization for worse spatial
localization/more ringing near edges, so comparing all three on the same
noise grid is itself a useful result, not just a parameter choice. The
benchmark script should call `filters` three times for this method and
treat "daubechies-db2", "daubechies-db4", "daubechies-db8" as three separate
rows/filters in the results table, the same way Haar/Meyer get their own row.

### 5.6 Shearlet Wiener
1. Forward shearlet transform via NSST Toolbox (or ShearLab).
2. Per-scale noise variance needs calibration: shearlet subbands are not
   unit-norm like orthogonal wavelets, so `sigma` must be scaled per
   scale/direction (standard trick: pass a unit-variance white-noise image
   through the same transform once and use the per-subband output variance
   as a calibration factor, or use the toolbox's documented noise-scaling
   utility if it ships one).
3. Apply the same empirical Wiener shrinkage helper per subband.
4. Inverse shearlet transform.

### 5.7 Curvelet Wiener
Same structure as shearlet: forward curvelet transform (CurveLab
`fdct_wrapping` or fallback), per-scale/angle noise calibration (curvelet
coefficients also need this — CurveLab ships a documented noise-calibration
routine for exactly this purpose), empirical Wiener shrinkage per coefficient
set, inverse transform.

## 6. Shared Local Helper Functions

- `sigma = estimateNoiseStd(image)` — Donoho MAD estimator on the finest
  wavelet diagonal detail band; used whenever `NoiseVariance == "auto"`.
  Reused across classical/fourier/wavelet branches so there's one estimator
  to validate, not five.
- `coeffsOut = empiricalWienerShrink(coeffsIn, noiseVar, windowSize)` —
  generic subband Wiener gain: local variance via a moving-average filter
  (`movmean`/`conv2`) on `coeffsIn.^2`, subtract `noiseVar`, clip at zero,
  apply the gain formula. Shared by Haar/Daubechies/Meyer/shearlet/curvelet.
- `checkToolbox(name)` — fail fast with an actionable message if NSST/
  CurveLab isn't on the path, before wasting time on the rest of a batch run.

## 7. Output Validation / Edge Cases

- Clip final output back to `[0,1]` (same convention as `image_prep.m`) —
  Wiener shrinkage and IFFT round-trips can produce tiny negative/`>1`
  excursions from floating-point noise.
- Guard against `options.WaveletLevel` being too deep for the image size
  (`wavedec2` errors on this) — clamp to `wmaxlev` or throw a clear message.
- Non-power-of-two image sizes (the test images won't all be square or
  power-of-two) must round-trip correctly through wavelet/shearlet/curvelet
  transforms — confirm this explicitly in testing, since it's the most
  common source of silent reconstruction bugs (off-by-one cropping).

## 8. Testing Plan Before the Full Benchmark

1. **Identity sanity check**: run every filter on a *clean* image
   (`images/clean/...` or `images/noisy/clean/snr_original/...`) — PSNR
   should stay high and SSIM near 1 for all seven (a filter that wrecks a
   clean image is broken).
2. **One image, one noise type, all seven filters** — visually inspect
   output + check PSNR improves vs. the noisy input before running the full
   `noise_type × snr_level × image` grid.
3. **Oracle vs. blind noise variance** — run once with `CleanReference`
   supplied (oracle) and once with `"auto"` (blind) on the same image, confirm
   oracle performance is ≥ blind (sanity check on the estimator).
4. Only after 1–3 pass, run the full grid (3 images × 6 noise types × 3 SNR
   levels × 7 filters = 378 runs) via the benchmark script.

## 9. Companion Benchmark Script (out of scope for `filters.m`, but drives its API)

Not part of this deliverable, but worth sketching so `filters.m`'s API lines
up: a driver (e.g. `run_wiener_benchmark.m`) reads
`images/noisy/noise_manifest.csv`, loads each `(Source, Output)` pair, calls
`filters` for each of the 7 methods with `tic`/`toc` around the call (or reads
`info.elapsedSeconds`), computes `psnr`/`ssim` against the clean source, and
writes a results table mirroring the manifest's style
(`Image, NoiseType, SNR, Filter, PSNR, SSIM, ElapsedSeconds`) to
`images/noisy/wiener_benchmark_results.csv`.

## 10. Risks

- **Curvelet/shearlet toolbox installation** is the single biggest schedule
  risk — start this first, confirm it builds on every teammate's machine
  before investing time in the shrinkage logic. See fallback in §3.
- **Per-subband noise calibration** for shearlet/curvelet is easy to get
  subtly wrong (unlike orthogonal wavelets, the "divide by 0.6745" MAD trick
  doesn't directly transfer) — verify against a known white-noise image
  before trusting results on real test images.
- **Runtime**: curvelet/shearlet transforms are noticeably slower than
  wavelets, and the `crowd` image is likely the largest — if execution time
  is a tracked metric, make sure slow filters don't blow up total benchmark
  runtime; consider timing out or downsampling during development iteration.
